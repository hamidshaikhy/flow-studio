## دو نوع وضعیت

گردش‌کار قابل ویرایش و نتیجهٔ اجرا جدا هستند. موتور هنگام شروع، یک clone از سند می‌گیرد. تنظیمات هنگام running، paused یا interrupted قفل می‌شوند. خروجی‌ها در undo و redo وارد نمی‌شوند. پس از ویرایش سند، نمایش نتیجهٔ قبلی از بوم کنار می‌رود ولی تاریخچه باقی می‌ماند.

ویرایش‌های متنی پیوسته با پنجرهٔ ۷۰۰ میلی‌ثانیه‌ای در یک action قرار می‌گیرند. جابه‌جایی در پایان drag ثبت می‌شود؛ حرکت‌های میانی فقط وضعیت نمایشی‌اند. تا ۵۰ تغییر قابل بازگردانی نگه داشته می‌شود. autosave با debounce ۴۵۰ میلی‌ثانیه و صف ترتیبی اجرا می‌شود؛ revision از اعلام Saved برای نسخهٔ قدیمی جلوگیری می‌کند.

کامپوننت‌ها کل Zustand store را subscribe نمی‌کنند. صفحه‌های کتابخانه، تاریخچه و راهنما lazy-loaded هستند. بوم و Inspector برای صفحهٔ اصلی فوراً در دسترس‌اند. CSV فرمول‌های رشته‌ای را با apostrophe خنثی می‌کند؛ واردکردن label و داده فقط به شکل متن React است و HTML اجرا نمی‌شود.

## تصمیم‌های محدودکننده

هر بلوک یک والد داده دارد؛ fan-out مجاز و fan-in ممنوع است. این تصمیم معنای شرط و بازیابی را روشن نگه می‌دارد. زمان‌بندی ترتیبی است و خروجی هیچ مرحله‌ای پیش از commit مصرف نمی‌شود. نه eval و Function استفاده شده، نه پردازش پس‌زمینه، proxy و سرویس AI.

Storage version فعلی ۱ است و در upgrade سه store ایجاد می‌شود. فایل و رکورد ناسازگار رد می‌شوند. برای نسخهٔ آینده باید migration صریح اضافه شود؛ نسخه‌های ناشناخته خودکار به نسخهٔ فعلی تبدیل نمی‌شوند.

WebMCP پیشنهادی و اختیاری است. در نبود API مرورگر هیچ وابستگی ایجاد نمی‌کند. ابزارها خلاصه را می‌خوانند، صفحه را عوض می‌کنند یا سند تازه‌ای از الگو می‌سازند؛ ابزار پنهان برای اجرای درخواست شبکه وجود ندارد.
