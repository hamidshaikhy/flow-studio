# گزارش بررسی

این گزارش نتیجهٔ بررسی واقعاً اجراشده است؛ امتیاز Lighthouse، benchmark عملکرد، نتیجهٔ CI راه دور یا انتشار عمومی ادعا نشده است.

## محیط

- Node.js 24.18.0 و npm؛ نسخه‌های دقیق کتابخانه‌ها در lockfile.
- Vitest 5.0.3، React Testing Library و fake-indexeddb برای تست‌های unit و integration.
- Playwright 1.63.0 با Google Chrome نصب‌شده روی دستگاه برای تست‌های مرورگر. مرورگر از راه متغیر اختیاری `PLAYWRIGHT_EXECUTABLE_PATH` انتخاب شد؛ مسیر شخصی در کد ذخیره نشده است. نصب مرورگر داخلی Playwright در این محیط انجام نشده بود.
- تست‌های مرورگر با IndexedDB واقعی مرورگر اجرا شدند. بررسی خروجی production با سرور preview جداگانه ثبت شده است.

## فرمان‌ها و نتیجه

| بررسی               | نتیجهٔ مشاهده‌شده                                                  |
| ------------------- | ------------------------------------------------------------------ |
| `npm run lint`      | موفق، بدون خطا یا warning کد                                       |
| `npm run typecheck` | موفق با TypeScript strict                                          |
| `npm test`          | ۵۱ تست موفق در ۷ فایل                                              |
| `npm run test:e2e`  | ۱۶ تست مرورگر موفق با Chrome نصب‌شده روی دستگاه                    |
| `npm run build`     | موفق؛ فایل‌های static و chunkهای React، canvas و schema ساخته شدند |

بسته به نصب مرورگر، اجرای دوباره روی سیستم خودت:

```bash
npm ci
npm run format:check
npm run lint
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
```

اگر مرورگر Chromium سازگار دیگری داری، `PLAYWRIGHT_EXECUTABLE_PATH` می‌تواند مسیر executable آن باشد. این بررسی با Chrome نصب‌شده روی دستگاه انجام شد؛ تست در همهٔ مرورگرها یا دستگاه‌های فیزیکی انجام نشده است. برای اجرای پیش‌فرض Playwright، ابتدا Chromium آن را طبق فرمان بالا نصب کن.

## پوشش رفتار

تست‌های موتور و داده شامل چرخه و اتصال نادرست، port، گراف غیرمتصل، شرط، ترتیب پایدار، مقدار ناموجود/null/false، CSV امن، نگاشت، خطاهای HTTP/JSON/content-type/شبکه/مهلت، pause/step/cancel، شروع تکراری، failure checkpoint و نتیجهٔ نامشخص نوشتن‌اند. schema ذخیره‌شدهٔ اجرا هم snapshot معتبر، node record کامل و خروجی موفق را بررسی می‌کند. تست رابط JSON، بازگردانی مقدار و اتصال‌های داخلی کپی‌شده نیز اجرا شده‌اند.

تست‌های مرورگر موارد زیر را پوشش می‌دهند:

1. پیکربندی فیلتر، درخواست کنترل‌شده و نتیجهٔ صحیح.
2. ساخت و اتصال با کنترل‌های قابل استفاده از صفحه‌کلید و undo/redo.
3. تأیید پاک‌کردن کل بوم، حذف هم‌زمان بلوک‌ها و اتصال‌ها، بازگردانی، انجام دوباره و ماندگاری بعد از reload.
4. بازشدن و اجرای سه الگوی پیچیدهٔ جدید با دادهٔ آزمایشی محلی.
5. هر دو نتیجهٔ شرط و صفر درخواست از مسیر ردشده.
6. خطای آزمایشی 503 و pending ماندن مراحل بعدی.
7. reload هنگام Delay، بازیابی snapshot و تکرار نشدن درخواست موفق قبلی.
8. لغو درخواست کند و پذیرش نشدن پاسخ دیررس.
9. دریافت/واردکردن فایل و رد فایل نامعتبر بدون از دست‌دادن اسناد.
10. ماندگاری پوسته و عرض ۳۹۰ پیکسل بدون overflow افقی.
11. فرمان‌ها و تک‌مرحله.
12. جلوگیری از ادعای مالکیت اجرا توسط زبانهٔ دوم.
13. POST قطع‌شده؛ رد تصمیم بدون درخواست جدید و تکرار فقط بعد از پذیرش صریح.
14. خطای واقعی write در IndexedDB مرورگر؛ توقف پیش از HTTP و ادامه پس از رفع خطا.
15. فایل‌های build زیر `/portfolio/`، مسیریابی hash و chunkهای lazy.
16. تصاویر واقعی، پنج بلوک در minimap و نبود خطای runtime هنگام مسیرهای بررسی‌شده.

## تلاش جداگانه برای API واقعی

`npm run test:live` بدون interception یا دادهٔ آزمایشی، درخواست واقعی مرورگر به `https://jsonplaceholder.typicode.com/posts` را امتحان کرد. **موفق نشد**: trace مرورگر خطای `net::ERR_EMPTY_RESPONSE` ثبت کرد و برنامه خطای شبکه را نمایش داد. علت دقیق از این نتیجه معلوم نیست؛ این گزارش آن را CORS یا خرابی کد معرفی نمی‌کند. موفقیت دسترسی زنده در این محیط تأیید نشده است.

این smoke test عمداً از تست‌های اصلی جداست، چون به شبکه و سرویس خارجی وابسته است. روی اینترنت خودت `npm run test:live` را اجرا کن. پاسخ واقعی سرویس با دادهٔ آزمایشی جایگزین یا موفق جلوه داده نشده است.

## تصاویر بررسی‌شده

۱۵ تصویر در `docs/screenshots/` از خود برنامه گرفته شده‌اند: ویرایشگر، تنظیمات، الگوها، شاخه‌ها، کتابخانه، نتیجه، تاریخچه و جزئیات آن، راهنما، اعتبارسنجی، خطا، بازیابی، تأیید پاک‌سازی و دو نمای موبایل. تصاویر دسکتاپ در عرض‌های ۱۶۰۰ و ۱۹۲۰ و تصاویر موبایل در اندازهٔ ۳۹۰ × ۸۴۴ ثبت شده‌اند. تصویر طراحی‌شده یا mockup در این پوشه وجود ندارد. اسکریپت `npm run capture:screenshots` آن‌ها را با پروفایل‌های مرورگر تازه بازتولید می‌کند.

نقشهٔ کوچک ابتدا خالی می‌ماند چون dimensions changeهای React Flow در وضعیت controlled نگه داشته نمی‌شدند؛ وضعیت measured جداگانه اضافه و تعداد بلوک‌های minimap در تست بررسی شد. نام accessible method و انتخابگرهای مبهم تست نیز اصلاح شدند. هشدار chunk بزرگ build با جداسازی واقعی کتابخانه‌ها رفع شد؛ اندازهٔ کلی یا سرعت فرضی به عنوان benchmark گزارش نشده است.

## بررسی اختیاری WebMCP

ثبت سه ابزار، اعتبارسنجی ورودی، استفاده از state رابط و cleanup در تست با context جایگزین بررسی شد. محیط دارای API بومی WebMCP برای بررسی ثبت واقعی در مرورگر نبود؛ **تأیید بومی این قابلیت انجام نشده**. نبود این API روی عملکرد عادی برنامه اثر ندارد.
